# Stage 3 — Retrieval-Constrained Qwen-Based Post-OCR Correction
### Build Specification for Autonomous Implementation

**Project context:** Handwritten descriptive answer evaluation system.
`Kraken (line seg) → Fine-tuned TrOCR (Stage 2) → Stage 3 (this doc) → Stage 4 (answer evaluation)`

**Non-negotiable design law (read first, obey always):**
> Qwen is a **decision-maker over a bounded candidate set**, never a free-form text generator.
> Every accepted correction MUST satisfy `selected_candidate in candidate_set`.
> If validation fails for any reason → **keep the original OCR text**. Missed correction is an acceptable failure. Incorrect/hallucinated correction is not.

## 3. Pipeline Flow (must match exactly)

```
OCR word list (Stage 2 output)
        ↓
[detector.py] suspicious token/phrase detection
        ↓
For each suspicious span:
    [candidates/aggregator.py] build bounded candidate set
    (SymSpell ∪ confusion-matrix variants ∪ domain dictionary hits ∪ phrase retrieval)
    → original token is ALWAYS included in the set
        ↓
    If |candidate_set| == 1 (only original) → skip Qwen, keep original
        ↓
    [qwen/verifier.py] send {prev_context, span, next_context, candidate_list}
        ↓
    [validation.py] hard structural validation of Qwen's JSON response
        ↓
    [gating.py] confidence/margin threshold check (tau_general / tau_domain)
        ↓
    Accept → apply replacement AND log; Reject → keep original AND log
        ↓
[pipeline.py] reassemble corrected_text from token stream
        ↓
[correction_log.py] persist full audit record for the page
        ↓
Stage3Result → Stage 4
```

## 4. Suspicious-Span Detection (`detector.py`)

Do not send every token to Qwen. A token/span is flagged suspicious if **any** of:

1. `word.confidence < conf_threshold` (from Stage 2 OCR confidence)
2. Token absent from **both** general dictionary and domain dictionary
3. Token matches a known character-confusion pattern from `char_confusion.json`
4. Token has unusual character patterns (repeated letters, digit/letter mix, no vowels, abnormal length vs. corpus average)
5. Token's edit distance to a domain-dictionary term is ≤ 2 but not an exact match
6. Token looks like a fragment of a merged/split word (very short token adjacent to another short token; or a token that is a substring/superstring of a domain term)
7. Local n-gram/phrase-level language-model or corpus lookup flags the surrounding phrase as low-probability (drives phrase-level candidates, Section 5D)

Implementation notes:
- Keep this a **cheap, rule-based/statistical** pass — no LLM calls here.
- Emit a `SuspicionRecord{token, span_ids, reasons[], severity}` for every flagged unit.
- Group adjacent suspicious single-token spans into a phrase-level span when they are contiguous (handles merge/split cases like `"local lacking"`).
- Everything not flagged passes through unchanged and is never shown to Qwen.

## 5. Candidate Generation (multi-source, `candidates/`)

Each source returns `List[str]`; the aggregator unions, dedupes, and **caps pool size** (e.g. max 6 candidates) before Qwen ever sees it. The **original OCR token is always injected into the final set** even if no source proposes it, so "keep as-is" is always a valid choice.

### A. SymSpell (`symspell_source.py`)
- Build/load a SymSpell dictionary (general English + domain dictionary merged, with frequency weights).
- Use a **small max edit distance** (start at 2; tune empirically — do not go to 3+ by default, pool explodes).
- Return top-k ranked suggestions.
- Example: `transisttor → [transistor, transistors]`.

### B. Empirical Character Confusion Matrix (`confusion_source.py`)
- Consumes `data/confusion_matrix/char_confusion.json`, generated by `scripts/build_confusion_matrix.py` (Section 6).
- For a suspicious token, generate candidate variants by substituting/collapsing characters according to the **highest-probability empirical confusion patterns** (e.g. `tt→t`, `i→e`, `rn→m`), then filter generated variants against the dictionary (general + domain) — only keep variants that are real words/terms.
- This is what catches errors SymSpell's generic edit-distance model may rank too low (OCR-specific confusions vs. generic typos).

### C. Domain Technical Dictionary (`dictionary_source.py`)
- Loads `data/domain_dictionary/ece_terms.txt` (ECE/VTU vocabulary: transistor, capacitor, resistor, inductor, amplifier, oscillator, modulation, demodulation, bandwidth, impedance, QPSK, BPSK, OFDM, CDMA, Rayleigh, Nyquist, Fourier, convolution, microcontroller, etc. — expandable, one term per line, versioned).
- Fuzzy-match suspicious tokens against this dictionary (edit distance + phonetic/shape similarity) to catch domain-term corruptions that general SymSpell would rank poorly (general dictionary biases away from technical vocabulary).
- Build this dictionary from: VTU/ECE syllabus, textbooks, this project's answer dataset, previously collected student answers. Keep it a plain versioned text file so it is easy to expand later.

### D. Phrase-Level / Domain Retrieval (`phrase_retrieval_source.py`)
- Build a small corpus of domain phrases/sentences (`data/phrase_corpus/domain_phrases.jsonl`) from the answer dataset + textbooks.
- Index with simple n-gram/TF-IDF or embedding similarity (local, no external API — e.g. `sentence-transformers` run locally, or simpler TF-IDF if latency-constrained).
- For a flagged **phrase span** (multi-token), retrieve the most similar phrases from the corpus and extract plausible replacement phrases.
- This is required for cases plain edit-distance cannot solve:
  - `"attack blood pressure"` → `"check blood pressure"` (semantic substitution, not a spelling fix)
  - `"local lacking"` → `"lactating"` (token merge / bad segmentation)
- Support explicit merge/split candidate generation: try concatenating adjacent suspicious tokens and re-checking against the dictionaries; try splitting a suspicious token at plausible boundaries and re-checking each half.

### Aggregation (`aggregator.py`)
```python
def build_candidate_pool(span, sources_output, max_pool_size=6) -> list[str]:
    pool = {span.original_text}  # original always present
    for candidates in sources_output:
        pool.update(candidates)
    ranked = rank_by_combined_score(pool, span)  # freq, edit-dist, source agreement
    return ranked[:max_pool_size]
```

## 6. Empirical Confusion Matrix Construction (`scripts/build_confusion_matrix.py`)

**Do not hand-write confusion rules.** Derive them from the Stage 2 dataset:

1. Take the Stage 2 held-out/train split: `(ground_truth_text, fine_tuned_trocr_output)` pairs.
2. Align each pair at the character level (e.g. Needleman–Wunsch / `python-Levenshtein` opcodes, or `difflib.SequenceMatcher`).
3. Tally every substitution, insertion, deletion, and multi-char pattern (e.g. `tt→t`, `rn→m`) with counts and normalized probabilities.
4. Persist as `char_confusion.json`:
   ```json
   {
     "substitutions": {"i->e": 49, "i->a": 29, "e->o": 26, "...": 0},
     "multi_char_patterns": {"tt->t": 0, "rn->m": 0},
     "insertions": {}, "deletions": {}
   }
   ```
5. Re-run this script any time Stage 2 is retrained — the matrix is model-specific, not universal.
6. Seed/sanity-check values from the current run are in Section 0 of this document; treat them as a smoke-test, not the final matrix.

## 7. Qwen Contextual Verification (`qwen/`)

### 7.1 Model loading (`model_loader.py`)
- Load the local Qwen model **once** at service startup; keep it resident (singleton/module-level cache). Never reload per request.
- Target device: local RTX 2050 (low VRAM) → prefer a quantized checkpoint (4-bit/8-bit via `bitsandbytes` or a GGUF build via `llama.cpp`/`ollama`, whichever the existing local install already uses).
- Set `max_new_tokens` very low (e.g. 20–40) — Qwen only emits a short JSON object, never prose.
- No external API calls; everything runs in-process/local.

### 7.2 Prompt template (`prompt_templates.py`)

System prompt (fixed, never modified per request):

```
You are an OCR correction verifier.
Your task is to select the most likely original word or phrase from the supplied candidate list.

Rules:
1. You may select ONLY from the candidate list.
2. Never generate a new word.
3. Never modify any other part of the sentence.
4. Never paraphrase.
5. Never improve grammar.
6. Never add information.
7. If the original OCR text is already plausible, select the original.
8. When uncertain, select the original.
9. Return only valid JSON. No explanation, no markdown, no extra text.
```

User message template:

```
Context (before): {previous_context}
OCR text: {ocr_text}
Context (after): {next_context}

Candidate list: {candidate_list}

Return exactly:
{"selected_candidate": "...", "confidence": 0.0}
```

- `previous_context` / `next_context`: a small local window (e.g. 5–8 tokens each side), never the whole page.
- Batch multiple independent spans from the same page into separate calls (or a batched generation call if the local runtime supports batching) — do not concatenate multiple spans into one prompt, that reintroduces free-form rewriting risk.

### 7.3 Verifier call (`verifier.py`)
- Sends the prompt, retrieves raw text output, does **not** trust it — passes straight to `validation.py`.
- Wrap generation in a try/except with a hard timeout; on any exception or timeout → treat as rejection (keep original).

## 8. Hard Output Validation (`validation.py`) — the safety boundary

Run **all** of these checks, in order, short-circuiting to "reject → keep original" on first failure:

```python
def validate_qwen_output(raw_output: str, candidate_set: set[str]) -> ValidationResult:
    # 1. Must parse as JSON (strip stray backticks/fences defensively, but do not
    #    accept trailing prose — if parsing fails after stripping, reject).
    # 2. Parsed object must contain exactly the expected keys:
    #    "selected_candidate" (str) and "confidence" (float).
    # 3. selected_candidate must be an EXACT string match (case-sensitive per your
    #    normalization policy — decide and document once) to a member of candidate_set.
    # 4. confidence must be a float in [0.0, 1.0].
    # 5. No additional keys, no nested objects, no extra free text alongside the JSON.
    # 6. The candidate must not itself contain whitespace-joined extra words beyond
    #    what was in candidate_set (defends against "transistor amplifier" style leaks).
    ...
```

If **any** check fails → `accepted=False`, `reason="validation_failed:<which_check>"`, original text is kept. This function must have unit tests covering every listed failure mode (Section 14) and must be provably unbypassable — the pipeline should be structured so applying a correction is *only* reachable through a successful `ValidationResult`.

## 9. Confidence & Margin Gating (`gating.py`)

- Maintain two thresholds in `config/thresholds.yaml`: `tau_general`, `tau_domain`.
- `tau_domain` applies when the flagged span matches/relates to a domain-dictionary term; `tau_general` otherwise.
- Accept only if `qwen_confidence >= applicable_threshold`.
- Optionally add a **margin** check if you expose multiple ranked candidates with scores (e.g. require the top choice to beat "keep original" by a minimum margin) to further bias toward conservatism.
- **Do not hard-code threshold values up front.** `scripts/calibrate_thresholds.py` grid-searches thresholds against the validation split, optimizing for a target trade-off (maximize correction precision & domain recovery while capping false-correction rate) — final chosen values get written into `thresholds.yaml` with the calibration run's metrics recorded alongside them for provenance.

- `original_text`, `corrected_text`
- full list of correction objects (Section 10), including rejected ones
- latency breakdown (Section 12)

This log is the primary artifact for debugging, the safety audit (Section 14), threshold recalibration, and paper result tables.

## 12. Latency Benchmarking (`scripts/benchmark_latency.py`)

- Report **Stage 3 latency only** — never combined with Stage 1/2/4.
- Measure and report separately: candidate-generation time, Qwen inference time, validation time, total Stage 3 time per page.
- Report **mean** and **P95** across the benchmark set.
- Target: **< 2 seconds per page**, on the local RTX 2050.
- Optimization levers to apply, in order of expected impact: (1) skip Qwen entirely for non-suspicious tokens, (2) load Qwen once/keep resident, (3) quantize the model, (4) cap `max_new_tokens`, (5) batch independent verification calls per page where the runtime allows it, (6) cache repeated (span, candidate_set, context) lookups within a run.

## 13. Evaluation Plan

### 13.1 Dataset
Use the **same held-out test split** as Stage 2. Ensure it spans: clean OCR, mildly corrupted OCR, severely corrupted OCR, technical terms, normal English, merge errors, split errors, phrase-level errors. Do not cherry-pick easy examples.

### 13.2 Comparison arms
- A. Ground truth
- B. Raw (non-fine-tuned) TrOCR
- C. Fine-tuned TrOCR (Stage 2 only)
- D. Fine-tuned TrOCR + Stage 3 (full system)

### 13.3 Metrics (`eval/metrics.py`)
1. CER
2. WER
3. Exact Match Rate
4. Correction Precision = correct corrections / total corrections applied
5. False Correction Rate = incorrect edits to originally-correct tokens / total originally-correct tokens
6. Domain-Term Recovery Rate = % of corrupted technical terms successfully recovered
7. Correction Recall = % of correctable OCR errors successfully corrected
8. Merge/Split Recovery Rate
9. Phrase Recovery Rate (contextual multi-word errors)
10. Stage 3 latency (mean, P95)

Do not assume Stage 3 improves CER/WER by default — report honestly, and if clean text is degraded, identify which condition causes it and recalibrate thresholds/candidate sources accordingly.

### 13.4 Ablation study (`scripts/run_ablation.py`)
Compare, on the same test set:
- (A) Fine-tuned TrOCR only
- (B) + SymSpell
- (C) + SymSpell + Domain Dictionary
- (D) + SymSpell + Domain Dictionary + Confusion Matrix
- (E) Full system + Qwen (strict candidate restriction)

Also run the explicit contrast required for the safety argument:
- (E1) Qwen **without** candidate restriction (free-form, for comparison only — never shipped)
- (E2) Qwen **with** strict candidate restriction (the production configuration)

### 13.5 Safety / hallucination audit (`scripts/run_safety_audit.py`)
- Invariant test, run over every logged correction: `assert selected_candidate in candidate_set` — must never fail across the full test corpus.
- Adversarial unit tests (`tests/test_adversarial_qwen_outputs.py`) that **mock** the Qwen call to return each of the following, and assert the pipeline rejects all of them and keeps the original text:
  - a candidate plus extra words (`"transistor amplifier"`)
  - a full sentence / explanation instead of JSON
  - malformed JSON
  - a candidate not present in the supplied set
  - missing keys / wrong types
  - valid JSON but confidence outside `[0,1]`
  - empty string / null output / timeout / exception from the model runtime

## 16. Definition of Done

- [ ] Every accepted correction traceable to a candidate produced by a named source.
- [ ] `assert selected_candidate in candidate_set` never fails across the full test corpus.
- [ ] All adversarial Qwen-output tests pass (reject + keep original in every case).
- [ ] Stage 3 mean and P95 latency reported independently, target < 2s/page met or gap explained.
- [ ] Four-way (GT / Raw TrOCR / Fine-tuned TrOCR / +Stage 3) metrics table produced.
- [ ] Five-way ablation table produced.
- [ ] Thresholds are calibrated from data, not hard-coded, with the calibration run logged.
- [ ] Correction log exists and is queryable for every processed page.
- [ ] No code path exists where Qwen's free text can reach `corrected_text` without passing `validation.py`.
